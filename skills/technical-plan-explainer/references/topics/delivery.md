# 交付验收与修订

先读 contracts 并执行项目校验，检查来源关联、事件、真实时间、母版一致与媒体。原生 HTML 的 GSAP 注册使用 inline script，便于框架静态检查；外部作者源码可由应用生成内联版本，保留来源与恢复点。

`project.mjs check PROJECT` 调用真实 hyperframes check --json --snapshots，记录前后输入指纹并保存结果。先前原生 lint/检查错误按当前 CLI 合同修复；再次检查使用新报告名并更新 delivery.native_check。bundle 脚本拒绝输入已变化、浏览器未执行或未通过的检查报告。

`bundle.mjs` 调用 composition 项目安装的官方 core/compiler，再内嵌其官方 player、媒体、字体及本地脚本。它不实现另一套动画/音频同步引擎。所有运行资源必须变为内嵌；未解析 src、字体、CSS import、图片或媒体资源直接报错。保留第三方许可，确认输出路径未占用。

浏览器配置由 adapter 解析，verify.mjs 对单文件实际阻断 HTTP/HTTPS 请求，检查媒体播放、暂停、1.5 倍速、前后跳转同一画面、末尾重播、章节暂停、阅读面板、窄屏和脚本异常。Native check 和浏览器检查均通过后，目视查看重要 proof_times，检查动画前、中、后能否回答学习问题，并试听新配音。

最终报告分别列内容理解、机制运动、声音/时序、播放、资源/文件、恢复、平台覆盖。程序的通过不等于听感或讲解质量通过。报告实际时长，保留缺口；不能把未执行或 browserSkipped 当成通过。

只改画面：声音、字幕保留，重做动画和检查。改一段正文：仅该段音频、cue、关联场景与后续偏移失效。母版/模型/参数变更：相关声音缓存失效。缓存匹配必须包括完整正文、提示词、原始母版摘要和模型参数。保存新修订目录和旧产物，已完成的媒体通过原 task_id 恢复，不因封装失败重复收费。
