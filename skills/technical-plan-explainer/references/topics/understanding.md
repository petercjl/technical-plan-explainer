# 理解技术方案

先确认资料正文版本及覆盖，目录、附图、表格、约束与附录都可能承载关键条件。HTML 只读取正文与图表语义，不执行其脚本；PDF/DOCX 的缺页和识别不足单独记录。

提取七类对象：业务问题、参与者、数据对象、动作顺序、状态变化、边界约束、收益与代价。再沿一个真实工作实例走主路径，检查每次状态转换是否有前提、谁负责执行、产生什么结果，以及失败后怎样确定结果。

优先注意影响用户判断的机制：本地与云端边界、权限/审批、数据出站、持久化、版本、一致性、失败恢复、费用与实施范围。按方案实际相关性选择，不凑固定章节数。

source-map 为每个结论保留引用 ID、原文摘录、章节/页码和来源文件。fact-map 将原文事实、教学示意、推断与待确认问题分开。假设吞吐、金额、效果和开发完成度需要依据；示意值显式标注。

同一概念用一致术语。版本冲突先定位影响范围，优先明确正文版本及实施范围；关键冲突问用户或缩小解释范围。没有阻碍的事实继续处理。完成标准：主路径及关键结论有来源，读者能知道哪些是已实现、计划或推断。
