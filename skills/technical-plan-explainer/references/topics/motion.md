# 让机制可见

先写学习问题，再选视觉原语。每个场景有持续主体、初始状态、触发动作、目标状态、旁白、来源、真实语音锚点和动作前/中/后 proof_times。

| 问题 | 对象和动作 | 能证明理解的画面 |
|---|---|---|
| 数据怎样流转 | 有稳定编号的对象沿连接移动，进入模块后发生加工 | 可追踪身份和路径，结果能对应输入 |
| 端云怎样分工 | 固定分区和边界，出站与返回用不同方向 | 本地执行与云端推理的区别清晰 |
| 何时需要批准 | 对象在闸门前停住，具体提案展示，批准后才能通过 | 等待、放行与参数绑定分别可见 |
| 变更为什么使授权失效 | 对照同一目标/参数指纹，变更触发失效与新确认 | 不是一个永久有效的“允许”按钮 |
| 怎样恢复 | 保存点、未确认回执、重连核验和明确分支 | 状态恢复与副作用重试有区别 |
| 为什么固定版本 | 活动任务握住旧版本，新任务连接新版本 | 正在执行与后台更新可区分 |
| 怎样避免重复 | 相同编号的重复请求汇入同一回执 | 一次效果与重复消息可区分 |
| 方案有什么取舍 | 同一案例经两条路径，使用同尺度 | 成本与所得均有依据 |

每场景组合少量有目的的动作，通常 2–4 个。连线必须连接真实对象；先有对象空间关系，再画路线。聚焦镜头帮助看清机制，完成后回到全局定位；文字在稳定状态停留供阅读。装饰不替代状态变化。

从 HyperFrames 当前 animation 索引选命名规则，读完整 recipe 再实现。持续状态采用一张工作台/单个合成图，多个独立硬切场景遵从当前子合成合同。原生暂停时间线注册完成后才交给运行时；不以墙钟、未注册动画或音频 currentTime 自造视觉时钟。

检查被解释对象本身的运动，记录阻挡、经过边界、变化与最终状态的实际截图。回退再跳到同一点应重建同一状态。端云分区、审批凭证、指纹和示例图表都必须符合方案事实或标为示意。
