# 用一次工作解释因果

讲解主线：先说明解决什么问题与整体地图，再跟一个持续主体走完一条任务路径，最后展开对判断有影响的机制、取舍与交付范围。主体可以是请求、文件、订单、权限凭证或版本；使用方案真实对象，示意编号只承担教学身份。

旁白说明“为什么、意味着什么”，舞台显示“经过哪里、发生什么变化”，依据面板承接细节查证。首次出现术语时跟一句通俗定义，保留其真实名称以便对照。原文代码、参数清单和名词堆叠不直接当口播。

每章先有一个要回答的问题，再写少量有因果连接的句子。可使用闸门、快递、账本等比喻，但注明其示意身份，并维持真实模块和权限关系。优先动作与后果，避免把产品收益写成未经证明的结果。

时长与信息量匹配。用户指定一分钟时选完整而窄的路径，说明覆盖范围；用户要解释完整方案时覆盖关键前提，按章节拆分，不机械压成一分钟。长篇配音语义分段，声音方法见 N5。

在配音前检查每句：是否对应事实/明确推断；省掉此句是否损失理解；是否能在画面中看到相关对象；读者能否复述关键边界。保存纯旁白正文，术语词典、分镜提示和来源另存，方便机械核对字幕覆盖。
